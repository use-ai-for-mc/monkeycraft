# Flutter 音频会话检查

日期：2026-09-19。本次检查覆盖 Flutter 的聊天链接分发、OpenAudioMc 与 MCParks headless WebView 服务、`StreamScreen` 生命周期恢复，以及 iOS/Android 后台媒体接线。没有使用真实园区网络会话、真实账户或真机网页音频。

## 链路事实

1. 服务器聊天的点击事件由 `lib/chat/chat_rich_text.dart` 分发。OpenAudioMc 的 `https://session.openaudiomc.net/` 链接交给 `OpenAudioMcService`；`monkeycraft://audio?type=mcparks-v1&url=...` 在 HTTPS 和 `mcparks.us` 域名校验后交给 `McParksV1Service`。MCParks 在连接前后应用已保存的音量。
2. 两个 IO 服务使用 `HeadlessInAppWebView`。OpenAudioMc 通过页面范围控件和 session URL 判断状态；MCParks 自动点击 Connect、检查页面状态，并以 Howler 管理播放和音量。两者都通过 `INFO` 包把连接状态送回现有 WebSocket。
3. `StreamScreen` 在显式关闭、返回登录和 `dispose` 前的关闭路径调用两个服务的 `disconnect()`；因此正常离开流页面会停止隐藏播放器。
4. `StreamScreen.didChangeAppLifecycleState` 在 `resumed` 调用两个服务的 `softRefresh()`。若 WebView 在后台被暂停、失去页面状态或断开，服务使用保存的会话 URL 重载；流视频本身在后台暂停并于恢复时按既有会话逻辑重连。后台时没有主动断开音频服务。
5. iOS `Info.plist` 声明 `UIBackgroundModes` 的 `audio`，并由 `AudioBackgroundPlugin` 在园区会话持有时设置 playback + `mixWithOthers`。Android Manifest 声明 `FOREGROUND_SERVICE`、`FOREGROUND_SERVICE_MEDIA_PLAYBACK` 和 `mediaPlayback` 前台服务；Dart 的最后一个园区 owner 释放时会停止服务。真实网页音频持续播放仍须在园区真机会话验收。

## 修复：串行会话操作和重复链接

聊天链接的调用端不等待 `connect()`。原实现中，两个紧邻链接在首次 `HeadlessInAppWebView` 初始化尚未完成时可并发进入连接流程；周期监测、恢复、断开也可与之交错。结果可能创建重复播放器，或让旧会话的导航覆盖新会话。

新增 `lib/audio/audio_operation_queue.dart`，并接入两个 IO 服务。连接、恢复、断开、释放、恢复检查和周期监测现在按单服务提交顺序执行。活跃服务再次收到相同会话 URL 时直接复用当前会话；不同 URL 保留原先“先断开旧会话再加载新会话”的行为。队列在一个操作失败后仍会继续执行后续操作，避免错误永久阻塞恢复或手动断开。

复核发现原始第一版串行化仍有三个边界，因此补充了最小修复。`initialize()` 在已有 WebView 时现为幂等；创建失败会清除半初始化引用。`connect()` 在加载失败后清除活跃状态，因此相同 URL 可重试。断开和释放会立即撤销活跃标志、停止计时器；恢复检查与周期检查都在异步页面判断返回后再次检查该标志，避免已经排队的旧检查把刚断开的会话重新导航。MCParks 在异步写入 Howler 音量后也重新确认会话仍活跃。周期检查改为“至多一个已排队或运行”，慢 WebView 不会每三秒累积新的检查任务；平台检查异常会发送一次可恢复的 `connected: false, error: monitor` 状态，下一周期仍可继续检查，而不会形成未处理异步异常。

为服务层测试新增 `AudioWebView` 适配接口。生产实现仍使用同一套 `HeadlessInAppWebView` 设置和 MCParks document-start 脚本；接口只允许测试注入可控 fake，不改变平台通道或播放协议。

## 后台媒体生命周期补充

两个园区服务在隐藏 WebView 成功载入会话 URL 后申请同一个后台媒体租约；连接失败、显式断开、页面故障和释放都会撤销。Dart 以 owner 集合和串行操作队列协调两个服务：第一个 owner 成功启动原生会话后才被记录，最后一个 owner 才停止。延迟启动后的释放排在启动之后；启动失败不留下 owner；最后停止失败会保留 owner，下一次释放会重试。非 Android/iOS 的 IO 平台使用显式 no-op 后端，测试不再依赖缺失的 MethodChannel 或生产超时。

iOS 新增 `AudioBackgroundPlugin`，在活跃时设置 `AVAudioSession` 为 playback 和 `mixWithOthers`，停止时以 `notifyOthersOnDeactivation` 释放；插件已注册并加入 Runner Sources。Android 增加 `AudioPlaybackService`，声明 `mediaPlayback` 前台服务类型及对应权限，显示低重要度的“MonkeyCraft audio”媒体通知；插件在 Flutter engine 清理时停止它自己已启动的服务。两个原生 MethodChannel 方法均为无参 `start` / `stop`，成功返回 void，失败返回平台错误。
