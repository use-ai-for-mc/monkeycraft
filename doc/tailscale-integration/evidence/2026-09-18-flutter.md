## Android 内嵌接线

- 复用仓内 `android/third_party/libtailscale/out` 的 arm64-v8a 与 armeabi-v7a `libtailscale` 产物，主 App 通过 CMake/JNI 加载。
- 新增 Method/Event channel 的 Android 实现：状态、交互式登录、节点与 peer 列表、持久化 state directory、注销清理、指定 peer 的 `tailscale_dial` 与本地 loopback bridge。
- Dart IO 客户端在 Android 启用；既有登录页复用同一用户登录、peer 选择与 nodeId 持久化流程。
- 运行时会探测 JNI 与当前 ABI：缺少 native library 时诊断返回 unavailable，x86/x86_64 不会伪装为可用；仅 arm64-v8a 与 armeabi-v7a 具有 libtailscale 产物。
- login 的 LocalAPI 请求有连接与读取超时，并轮询 AuthURL；取消和停止关闭 node，bridge 校验 port/lease，关闭本地 listener、已接受 socket 与 native fd。

## 证据边界与待测

- APK 编译不能证明 Android `untrusted_app` 进程能绕过 netlink 限制，也不能证明登录、恢复、Doze、网络切换或用户态 TCP bridge。当前没有 adb 设备，未运行真实设备或模拟器验证。
- iOS 编译不等同于真机登录、通知、音频后台或内嵌传输验证。
- Android 只带 arm64-v8a、armeabi-v7a 两个 libtailscale ABI；x86/x86_64 Flutter 构建使用不可用 JNI 占位实现，不能把模拟器作为 Android 内嵌成功证据。
- 本机重新核验 `out/MANIFEST.json`、源码 git HEAD 和两 ABI SHA：来源为 `https://github.com/tailscale/libtailscale.git` 的 `80771313ac4127973677c993889fe215abcf1fbd`，产物 SHA 与 manifest 一致。构建脚本可从该 pin 重建。

## iOS AuthURL 延迟复现与登录体验修复

- 在 arm64 iPhone 16 模拟器（iOS 26.5，UUID `F22F02AB-CE7D-4414-A55D-C0EE6757A84D`）使用固定 libtailscale pin、全新临时 state directory 运行原生 opt-in XCTest。它执行 `startNode`、状态读取、`loginInteractive`，每 250 ms 读取状态至首次非空 AuthURL（最长 60 秒）；不授权、不记录 URL、令牌、状态 JSON 或密钥。
- 该次完整测试在 20.782 秒通过。其 XCResult 附件的脱敏毫秒数据为：`startMs=78`、`localApiRequestMs=71`、`firstAuthURLMs=20689`。附件从 `/tmp/monkeycraft-ios-native-timing-3.xcresult` 导出至 `/tmp/monkeycraft-ios-native-timing-attachments/5527FFC7-40D9-49B1-AF0F-6C6A705AEA0A.json`。
- 因为纯 Go v1.94.1 基线也已复现首次 AuthURL 8–34 秒，且本次本地 LocalAPI POST 仅 71 ms，这不是 Flutter、Swift 队列、URLSession 或系统浏览器打开造成的首要延迟。根因继续由固定 Go 模块的控制面分段日志调查；本轮未更换登录传输或 Go 库。
- iOS 原生层现在记录不含敏感数据的阶段耗时：C archive 创建/启动、状态、loopback、LocalAPI 请求，以及系统浏览器打开完成。`UIApplication.open` 改为异步完成回调，结果回到 manager queue 并按 generation 和 AuthURL 去重；不会在主线程等待回调。显式 `loginInteractive` 会允许重新呈现同一登录页；失败后下一次 start 会关闭旧 backend，幂等 start 保留已发现 peers。
- 登录页在尚无 AuthURL 时显示“正在准备登录”，不会再声称网页已打开；收到 AuthURL 后提示完成登录并可重新打开页面，页面不显示 hostname 或 URL。
- Swift XCTest：`xcodebuild test -workspace ios/Runner.xcworkspace -scheme Runner -destination 'platform=iOS Simulator,id=F22F02AB-CE7D-4414-A55D-C0EE6757A84D' -only-testing:RunnerTests` 通过，原生网络计时测试默认跳过，避免普通测试触网。Dart 登录页测试 6 项通过。
- 真机仍未运行此测试：同 bundle 的 XCTest 会安装测试 host，可能覆盖用户正在登录的 App。若需真机采集，应使用独立 bundle ID 的诊断 host，并把同一脱敏阶段 JSON 写到其 app container；不得使用 `flutter install` 或手动终止现有 App。
- 为后续真机诊断增加了默认关闭的 Swift 编译条件 `MONKEYCRAFT_TAILSCALE_TIMING`。启用时写入 app data container 的 `Library/Caches/MonkeyCraftDiagnostics/tailscale-timing.jsonl`；文件最多 64 KiB，满时从新事件重新开始。每行只有 `stage`、`monotonicMs`、`elapsedMs` 和可选枚举 `phase`，不包含 URL、host、IP、令牌、node ID、完整 status 或密钥。
- 阶段包括 `start.entry`/`start.return`、`login.entry`/`login.return`、`authURL.first`、`systemOpen.entry`/`systemOpen.complete`，以及 C archive 的启动、状态、loopback 和 LocalAPI 耗时。系统打开仍为异步回调，没有新增等待或阻塞。
- 已用以下命令编译并运行带诊断宏的 iOS 模拟器 RunnerTests，全部通过：`xcodebuild test -workspace ios/Runner.xcworkspace -scheme Runner -destination 'platform=iOS Simulator,id=F22F02AB-CE7D-4414-A55D-C0EE6757A84D' -only-testing:RunnerTests SWIFT_ACTIVE_COMPILATION_CONDITIONS='$(inherited) MONKEYCRAFT_HAS_LIBTAILSCALE MONKEYCRAFT_TAILSCALE_TIMING'`。真机只构建、不安装的同等命令为：`xcodebuild build -workspace ios/Runner.xcworkspace -scheme Runner -configuration Debug -sdk iphoneos -destination 'generic/platform=iOS' CODE_SIGNING_ALLOWED=NO SWIFT_ACTIVE_COMPILATION_CONDITIONS='$(inherited) MONKEYCRAFT_HAS_LIBTAILSCALE MONKEYCRAFT_TAILSCALE_TIMING'`。

- 未使用现有 `tailscale_set_logfd` 采集 native 日志。固定 pin 的实现把传入 fd 交给 Go `os.NewFile`，但 close 和重新设为 discard 都不关闭该 fd；完整 Logf 还可能包含 URL、key、header。Swift pipe 因而既可能泄漏或阻塞 backend，也不能先写入原始敏感日志再过滤。若需要记录已证实的 register 502 重试，必须在固定 pin 的诊断专用 archive 中实现上限 ring buffer，并只导出 `stage`、HTTP status 和单调耗时的窄 C API。
