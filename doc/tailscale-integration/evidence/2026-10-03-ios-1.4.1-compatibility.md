# iOS 1.4.1 与当前 26.2 Mod 的模拟器连接验证

日期：2026-10-03（Asia/Singapore）。用户明确要求在模拟器运行旧版 1.4.1，连接目前的 Mod。结论：**密码认证、进入游戏画面和持续原生 H.264 解码通过**。

## 实际环境与来源

- 客户端：`v1.4.1` 标签，提交 `f309c4fccd6922337afb70b24b48f628b7066760`；归档到 `outputs/ios-1.4.1-compat-2026-10-03/source/` 后重新编译。安装包为 `1.4.1 (10)` Debug，Flutter 3.41.2 / Dart 3.11.0。本次不是 App Store 分发的 `1.4.1 (11)` 真机二进制。
- 150 个已跟踪文件逐一比较，Dart、Swift、项目配置及 Dart 依赖锁文件保持原版；只有 `ios/Podfile.lock` 被本机 CocoaPods 从 1.11.3 更新到 1.16.2，变动为工具版本和本地 podspec checksum，依赖版本未改变。
- 模拟器：新建 iPhone 16，iOS 26.5，UDID `FE1EBC7D-C825-4784-81E3-082787324C07`。未替换实体手机 App 或原有模拟器数据。
- Mod：正在运行的 PrismLauncher `ImagineFun Add-Ons` / Minecraft 26.2，`monkeycraft-1.4.2-26.2.jar`，SHA-256 `6e1dd7fbd7330842844b505da8ce9c8736353f4418374369bbbf47e851147d67`。运行时 Fabric 元数据确认加载此 JAR；`git diff 83bdb01..04213b5 -- mods/26.2` 为空，当前 Mod 树与部署来源相同。
- 连接：模拟器直连 `127.0.0.1:9600`，使用现有 Mod 密码。未关闭认证、未修改密码、未使用 Tailscale。测试开始前确认没有控制客户端占用。

## 执行与结果

1. `flutter pub get --enforce-lockfile` 成功。首次 `flutter build ios --simulator --debug --no-pub` 在 Flutter 的双架构检查失败；保留 `build.log`。改用 `xcodebuild -workspace ios/Runner.xcworkspace -scheme Runner -configuration Debug -sdk iphonesimulator -destination 'id=FE1EBC7D-C825-4784-81E3-082787324C07' ARCHS=arm64 ONLY_ACTIVE_ARCH=YES CODE_SIGNING_ALLOWED=NO build` 成功，未修改产品源码。
2. 通过 `flutter run --use-application-binary` 启动实际 App。本机独立 `Simulator.app` 不存在，CoreSimulator 可正常运行；使用 Dart VM 调试接口填入现有凭据并调用原版 `_LoginScreenState._connect()`，没有跳过其密码认证或自行构造替代客户端。
3. 原版登录流程进入游戏页；模拟器真实屏幕截图显示 Minecraft 画面和旧版操作界面。Mod 同时报告 `connected=true`、`streaming=true`、`inWorld=true`。
4. 11:28:53 的原生解码器统计为输入/解码均 535 帧；11:30:09 均为 1200 帧，`droppedAccessUnits=0`、496×960、目标 10 FPS。客户端 `connected=true`、`showVideo=true`、`reconnectRetryCount=0`。仅说明本次基本连接及视频兼容，不扩展成性能或所有功能验收。
5. 正常停止测试连接，结束测试 App 并关闭新建模拟器。Mod 最后报告 `connected=false`、`streaming=false`、`inWorld=true`；没有重启 Minecraft 或发送移动/攻击等游戏输入。

旧版 Debug 启动时，键盘预热用的隐藏 `TextField` 报 `No Material widget found` 断言；保留在 `run.log`。它未阻止登录和视频渲染；本次未改旧版源码来消除此断言，也不据此宣称 App Store Release 存在相同表现。
