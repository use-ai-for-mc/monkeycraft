# iOS 模拟器原生 H.264 回放（2026-09-19）

## 范围

在 Workbench iPhone 16（iOS 26.5，`F22F02AB-CE7D-4414-A55D-C0EE6757A84D`）上运行生产 `StreamProxy`、`SessionController`、`HardwareH264Decoder`、`VideoSurface` 与 iOS `H264DecoderPlugin`/VideoToolbox。输入是本机 `streaming-360x640` 回放夹具，不连接 Minecraft、Tailscale、账户或真实 iPhone。

回放服务在仓库根目录启动：

```text
node web/tools/replay-server.ts --port 9601 --fixture streaming-360x640 --password test
```

iOS Simulator 可直接访问主机的 `127.0.0.1:9601`，不使用 Android 的 `adb reverse`。在 `flutter/monkeycraft` 执行：

```text
flutter test integration_test/native_stream_h264_replay_test.dart \
  -d F22F02AB-CE7D-4414-A55D-C0EE6757A84D \
  --dart-define=replayServer=ws://127.0.0.1:9601 \
  --dart-define=replayPassword=test
```

## 结果

测试通过（1 项）。首次编译因新夹具缺少`foundation.dart`导入而失败，补齐测试导入后重新执行通过；不是生产解码器失败。首次连接与释放后的重连都经过 HMAC 握手、`CLIENT_STATUS`、二进制 access unit、VideoToolbox 输出和 ACK；回放服务最终为 `clients=0`、`streaming=false`、`framesSent=14`、`dropped=0`。

| 连接 | inputAccessUnits | decodedFrames | droppedAccessUnits | 尺寸 |
| --- | ---: | ---: | ---: | --- |
| 首次 | 6 | 6 | 0 | 360×640 |
| 重连 | 6 | 6 | 0 | 360×640 |

每轮先要求 `decodedFrames >= 5`，再次读取必须继续增长；同时要求 native input 大于零、纹理存在与 360×640 尺寸。释放顺序为卸载 `VideoSurface`、取消帧订阅、停止 `StreamProxy`、释放 decoder，并断言原生 `getStats` 返回空 map，然后在同一个 proxy 上重新连接并重复验收。

iOS 的 `decoding` 不作为持续 true 的断言：VideoToolbox 实现在当前 decode queue 排空后会将该字段设为 false，而 Android MediaCodec 将其保持到 stop。iOS 未放宽关键验收，实际输出 callback 增加的 `decodedFrames`、后续增长、尺寸与释放后空 stats 才是解码和资源回收的证据；Android 继续保留 `decoding=true` 断言。

测试结束后以 Ctrl-C 正常停止回放服务，并执行 `xcrun simctl shutdown F22F02AB-CE7D-4414-A55D-C0EE6757A84D`。确认回放端口不可连接且该模拟器为 Shutdown。没有操作真实 iPhone。
