## 精确最小工作面

### 可先移植的纯服务层

1. 新增 `tailscale/HelperTailscaleService.java`、`NativeHelperExtractor.java`、`TailscaleSnapshot.java`。它们只依赖 Java 25、Gson、Fabric Loader 与 `MonkeycraftClient.LOGGER`；没有 Minecraft GUI API。
2. 新增 `server/HttpAwareWebSocketServerFactory.java`、`HttpOrWebSocketChannel.java`、`WebAssetServer.java`，并仅在 26.1 `MonkeycraftWebSocketServer` 构造器接入 `setWebSocketFactory(...)`。
3. 在 26.1 `WebSocketServerHandler.shutdown()` 中关闭 helper，并移植经过 26.2 验证的端口可用性实现。不要顺带移植 26.2 的配对来源限制、设备名、`keyId`、`PasswordKey` 或删除 `TailscaleAccess`；它们不属于同端口 Web/helper 的必要依赖。
4. 新增 `utils/TailnetHttps.java`。它只读取 `tailscale status --json` 和 `tailscale serve status --json`，只在其代理目标严格等于当前 MonkeyCraft 端口时返回链接，不修改 Serve/Funnel。

### 26.1 必须保留并增量修改的部分

1. 保留 `config/ConfigScreenFactory.java`、Cloth Config 依赖和 `TailscaleAccess`。26.2 已移除这些并改为 `MonkeyPanelScreen`/向导；整块复制会删除 26.1 的既有网络范围迁移与配置入口。
2. 在 `ModConfig` 仅增加 `embeddedTailscaleEnabled`，以及 helper 所需的非秘密状态字段（若 UI/状态确实使用）。既有 `password`、`networkScope`、`tailscaleAccess` 与迁移代码必须保留。`passwordId`/`PasswordKey` 只在单独移植新配对协议时引入，并同时迁入其测试。
3. 在 `MonkeycraftClient` 按 26.1 API 接入：客户端停止时 `HelperTailscaleService.shutdown()`；自动启动成功后仅在显式开关为真时 `ensureRunning(port)`；增加 `tailscale login/status/logout/stop` 命令；在既有 Cloth 配置页添加开关和状态入口。默认关闭，不能自动读取、移动或删除任何 Tailscale 身份。
4. 第一轮不要移植 `MonkeyPanelScreen`、`SetupWizardScreen`、`HomeCopy`、`PanelScrollArea` 或 26.2 的 pairing prompt。它们是独立 UI/配对产品变更，且使用 26.2 的屏幕 API。

### 构建与资源

26.1 的 `build.gradle` 当前没有 helper manifest/hash/protocol/platform/license 检查，也不会将 `web/dist` 打进资源。应移植 26.2 的行为而非覆盖其 Loom、Fabric、Cloth Config、ModMenu 或 API 版本：

1. `processResources` 前验证已生成的四个正式支持 helper（darwin-amd64、darwin-arm64、linux-amd64、windows-amd64）的 manifest、SHA、大小、协议版本与 `LICENSE.tailscale`。
2. 复制这些 helper/manifest/SHA/许可证到 `native/tailscale/...`，并复制 `web/dist` 到 JAR 的 `web/`。
3. `web/dist/index.html` 缺失时失败；发布辅助脚本先执行 Web 与 helper 生成，再执行 format、clean build。
4. 输入产物现在被各自 `.gitignore` 忽略，不能把本机生成的 `web/dist` 或 `native/tailscale-helper/dist` 纳入版本控制；可重建的脚本、固定版本、patch、许可证与 manifest 校验逻辑必须被跟踪。
