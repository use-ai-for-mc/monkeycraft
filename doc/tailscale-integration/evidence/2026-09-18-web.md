| 项目 | 当前行为 | 自动化证据 |
| --- | --- | --- |

| 双响 | 隐藏标签页成功创建系统通知时不播放页面声音；系统声音最终仍由浏览器和 OS 决定。 | `ReminderAlerts` 单元测试 |

| 刷新边界 | 本标签页 sessionStorage 记录最近 32 个已触发提醒指纹，刷新后同一提醒不会再响；新 tab 仍由现有 tab lock 防止同时控制。 | 代码审阅；需要真实浏览器补验 |

| 留黑映射 | Pillarbox 黑边点击不发送 `SCREEN_CLICK`，画面中心点击仅发送一条归一化点击。 | Chromium Playwright 回放 |

提醒身份使用 `fireAtEpochMs` 加标题和正文的非内容持久化指纹；服务端只更新倒计时文本时不会二次提醒。标题或正文变化代表不同提醒，符合“同一时间多个不同活动”的场景。

## 浏览器环境探测

- Chromium 1243 已安装，回放、WebCodecs 基线、缩放、输入和黑边坐标回归均通过。
- Playwright WebKit 26.6 已安装。有限录像回放原先在固定 500ms 等待后直接关闭 `VideoDecoder`，WebKit 尚有 16 个已送入队列的 frame 未输出。测试收尾现在调用 WebCodecs [`flush()`](https://www.w3.org/TR/webcodecs/#dom-videodecoder-flush) 排空队列（仅有限回放，实时流不调用），保留原有近乎全帧阈值；单线程完整回放为 17 通过、2 个真实连接项跳过。该 API 保证在 promise 完成前输出先前排队的帧，而 `close()` 会中止待处理工作。桌面 WebKit 仍不代表 Safari 或手机实机验收。
- 未连接 iPhone、Android 或实际手机浏览器。本轮 Chromium 仅代表桌面自动化覆盖。

## 真实 26.2 验证准备

目标 WebSocket：`ws://127.0.0.1:9600/`；正式 HTTPS 入口：`https://mac.tail977122.ts.net:8443/`。本轮不修改 Serve/Funnel。

新增 `web/tools/run-live-test.ts`：只在子进程内读取本机 Prism 实例的 `monkeycraft.json` 密码字段，传递给 Playwright 环境变量，不输出、不持久化该值；live spec 禁用 Playwright trace。它启动本地 Vite 开发代理，完成后停止该代理，不启动或停止 Minecraft。

可在最终 jar 重启且真实游戏已自然进入服务器后运行：

```bash
cd /Users/cusgadmin/if-local/monkeycraft/web
node tools/run-live-test.ts
MONKEYCRAFT_LIVE_SOAK=1 node tools/run-live-test.ts
```

第二条命令在同一真实连接上运行 10 分钟：每 140 秒改变一次视口，并在每段采样持续解码、零 decoder 错误和连接状态。它不把 SPS 改变引起的 decoder 重新配置误判为失败。普通 live 测试还会通过正式 UI 登录、等待解码，并以 `E` / `Escape` 检查库存 screen state。真实 HTTPS、安全上下文已在下述最终 jar 验收；通知授权/声音听感和黑边点击仍需真实移动浏览器验收。

若本地 Vite 已由其他测试占用 5173，可显式复用它：

```bash
MONKEYCRAFT_REUSE_DEV=1 node tools/run-live-test.ts
```

`MONKEYCRAFT_LIVE_URL=https://mac.tail977122.ts.net:8443` 会让页面直接使用该 HTTPS 入口的同源 WSS；wrapper 不会设置任何 TLS 绕过选项。

最终 jar 已部署重启后，使用 `MONKEYCRAFT_LIVE_URL=https://mac.tail977122.ts.net:8443` 直接加载正式 HTTPS 页面并保留 TLS 校验。普通 live 验收通过：`isSecureContext=true`、同源 WSS 认证、正式 picker 进入已保存的 `mp.imaginefun.net`、视频解码、`E` 打开库存与物理 `Escape` 关闭库存均成功。

随后以同一 HTTPS 入口运行显式 10 分钟 soak：四段各 140 秒的缩放采样及末段 40 秒均持续解码，连接保持 connected，decoder error 为零，测试最终状态为 passed。运行期间不记录 Playwright trace，也不输出或保存凭据。该结果是桌面 Chromium 的真实 PC 验收；尚未代表 iPhone、Android 或移动浏览器。

## 旧 26.2 jar 的真实链路结果（非最终构建）

本轮在最终 jar 重启前，以本地 Vite 代理连接 `ws://127.0.0.1:9600/`：认证、视频解码、通过产品 picker 选择已保存的 `mp.imaginefun.net`、自然进服，以及 `E` 打开库存和 palette 均成功。

首次运行中，物理 `Escape` 关闭库存后，palette 在 5 秒内没有消失。定位到浏览器 Pointer Lock 的竞态：`SCREEN_STATE` 到达时，旧实现依赖尚未同步的缓存布尔值，未必调用 `document.exitPointerLock()`，因而下一次 Escape 可能被浏览器消费。改为直接检查 `document.pointerLockElement` 并等待其解除后，用同一旧 jar 重测：认证、picker 进入 `mp.imaginefun.net`、解码、`E` 打开库存和物理 Escape 关闭库存均通过；串行的 10 分钟 soak 仍未开始。该 jar 仍不是最终构建，最终 jar 必须重复这项验证。live trace 已关闭；失败页面发生在登录后，未记录密码。
