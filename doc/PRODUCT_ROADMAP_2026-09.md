## 1. 已确认的产品决定

1. Flutter iOS / Android 是长期维护的正式客户端，保留通知、锁屏倒计时、后台园区音频和游戏控制。不要因浏览器客户端成熟而停止 App 发布。
2. 浏览器客户端是长期正式产品线。2026-09-19 用户更新决定：使用 Flutter 与 iOS / Android 共用界面和业务逻辑，浏览器差异通过专用适配层实现；独立 TypeScript / Preact `web/` 暂留作参考与测试资产，停止继续验收和发布该实现。Flutter Web 服务手机和桌面浏览器。保留页面内提醒，补齐浏览器允许的提示音和系统通知，不承诺页面关闭或手机锁屏后的可靠实时提醒。
3. LAN 和系统 Tailscale 是正式支持路径。已有 Tailscale VPN 常开的用户可以继续沿用。
4. PC 和移动 App 双端内嵌 Tailscale 是目标产品路径，用户不必另装 Tailscale 软件，但可以在 MonkeyCraft 内登录自己的 Tailscale 账户并授权节点。
5. 系统与内嵌方式允许混用，不因开发内嵌而删除已有连接方式。Tailscale 负责可达性，MonkeyCraft 的配对 / HMAC 仍负责应用授权。
6. 当前浏览器路径假设设备已有系统 Tailscale，或通过可用的 LAN 入口访问。不要求当前网页自行运行 Tailscale。
7. **保留托管网页入口阶段，当前优先 GitHub Pages，安排在现有浏览器路径测试稳定之后。** `www.monkeycraft.com` 仅为原候选域名，尚未购买或确认可用；自定义域名可后续替换，不阻塞项目地址验证。用户已有相关开发经验和探索成果，应先复用已有实现。这个阶段不必等待所有内嵌和 Mod 版本移植完成。
8. 不再来回拆除产品线；以增量实现、兼容已有用户和明确验收为原则。

## 3. 支持边界

| 客户端 | 网络目标 | 能力目标 |
|---|---|---|
| iOS App | LAN、系统 Tailscale、内嵌 Tailscale | 游戏、聊天、原生通知、Live Activity / 倒计时、园区音频 |
| Android App | LAN、系统 Tailscale、内嵌 Tailscale | 游戏、聊天、原生通知、chronometer / 倒计时、园区音频 |
| 手机浏览器 | 当前为 LAN / 系统 Tailscale，需满足安全上下文要求 | 游戏、聊天、页面提醒、可用时声音和系统通知 |
| 桌面浏览器 | 当前为 LAN / 系统 Tailscale，需满足安全上下文要求 | 游戏、键鼠操作、聊天、前台和后台标签页提醒 |
| 后续托管网页 | Flutter Web 在现有浏览器稳定后接入Pages | 复用 Flutter App 的 UI / 业务代码，新增托管入口 |

- 当前 WebCodecs 路径需要安全上下文。远端裸 LAN HTTP 和裸 `http://100.x` 可达，不代表可以解码视频。明确 HTTPS 入口及不支持时的提示，不把开发机 localhost 结果当成跨设备结果。
- Tailscale Serve 的 tailnet HTTPS 地址不等于公网可达地址。
- 浏览器自定义声音由页面音频播放实现；系统通知是否发声由浏览器和 OS 控制。避免双响，并遵守 `sound=false` 的适用语义；平台无法完全控制时如实说明。
- App 已安排的本地倒计时，与后台新收到的实时 NUDGE 是不同能力。实时消息依赖连接存活，测试与说明不能混淆。
- 换设备访问不等于多设备同时控制。先保持现有单会话约束；多设备旁观、并发控制、通知广播属于需用户另行确认的范围。
- 不为统一 UI 而削弱 App 能力。共享协议和行为语义，允许平台实现不同。

### P1：App 回归与 Web 收尾

Flutter：

- 验证 iOS、Android 的 LAN / 系统 Tailscale 连接、配对、游戏输入、断线恢复。
- 验证 NUDGE、倒计时创建 / 更新 / 取消 / 到点，以及断线后本地计时行为。
- 验证 OpenAudioMc、MCParks 音频与后台恢复。先核对实际聊天链接触发路径；外部适配器提供的 `monkeycraft://` 重写不可假定属于本仓库。
- 修复阻碍现有正式能力的回归，避免无关重构。

Web：

- 增加明确的启用提醒、测试声音操作；通过用户手势解锁音频，并处理权限拒绝、音频挂起和不支持情况。
- 落实 NUDGE 的声音开关和倒计时到点提醒；处理更新、取消、重连、页面恢复，防止重复或过期响铃。
- 验证页面内横幅与后台系统通知，不将 OS 是否发声当作网页完全可控能力。
- 完成持续运行、画面缩放 / 留黑坐标映射、桌面输入、手机触控、横竖屏、断线恢复。
- 验证真实 HTTPS 入口和安全上下文；核对 Web 资源打包进 Mod 的完整构建链。
- 园区音频保留浏览器平台可提供的路径，明确 App 与浏览器的差异；不得以 Web 不支持为由删除 App 功能。

验收：目标浏览器和 App 的核心路径有可追溯结果；提示音不是仅有协议字段；不具备设备条件的测试明确标记待测。

### P2：双端内嵌产品化

推荐逐段实施，每段先与已知可用的另一端互通：

1. **iOS 内嵌 → PC 系统 Tailscale**：核实现有代码，完成登录、节点选择、连接、重启身份恢复、断网和前后台恢复。
2. **PC helper**：完成 Java 集成、二进制分发、生命周期、登录入口、状态存储、端口转发、错误诊断和升级。目标是用户不用另装软件；不要求 Go SDK 必须直接运行在 JVM 内，随产品管理的 helper 可以满足目标。
3. **Android 内嵌**：完成原生桥接、登录、拨号、生命周期和打包，并验证用户已有 VPN 时的实际行为。
4. **组合验收**：系统 / 系统、内嵌 / 系统、系统 / 内嵌、内嵌 / 内嵌；最终覆盖 iOS 和 Android。

共同要求：

- 不硬编码可复用 auth key；用户登录自己的账户。
- 系统节点与内嵌节点身份独立，UI 和诊断能区分，不静默切换账户或 tailnet。
- 保持 MonkeyCraft 配对、HMAC 和能力协商，不因有 tailnet 身份而绕过应用鉴权。
- 验证系统 Tailscale 常开、节点撤销、登出 / 换账户、电脑和手机重启、网络切换、直连 / 中继。
- 系统网络已经可用时，用户无需强制再登录内嵌节点；LAN 与直接地址连接继续可用。
- 检查各平台构建、许可声明和发布元数据；iOS 加入内嵌网络组件后的出口合规答案需按实际产品重新核实，不机械照抄旧文档，也不擅自代替用户完成申报。

验收：新鲜安装、升级安装和真实跨设备连接均有证据；仅编译成功不能称为双端内嵌完成。

### P3：扩展 Mod 版本覆盖

以稳定的 26.2 实现为参考，将适用的 Web 服务和内嵌集成移植到 26.1、1.21.11、1.19，保持各自 Java / Minecraft API 要求。

- 先检查本地反编译 Minecraft 代码，不凭网上类名和方法签名猜测。
- 各版本分别构建和测试；无法提供相同能力时列出具体原因和降级行为。
- 与旧 Mod 互通使用现有 capability 机制；新增协议时更新协议文档和两端处理。

验收：四版本能力表准确，构建通过，不破坏已有 App 连接路径。

依赖：P1 的现有浏览器路径在目标设备上稳定验收。无需机械等待 P2 / P3 全部结束。

1. 查找仓库内既有网页入口、WASM、代理等探索成果；不要把未跟踪实验自动删除或直接当作可发布实现。

尽量执行自动化和实机测试，但不虚构可用设备、账户、网络或测试结果。

### 自动化

- Web：读取 `web/package.json`，运行适用的 lint、类型 / 构建检查、单元测试和 Playwright 测试；复用真实录制 fixture 和回放服务器。

- Go helper：按实际模块运行 `go test ./...`，对支持环境运行相关 race 测试和 Java harness。

### 集成与实机

- 手机：iOS App、Android App、Safari、Android Chrome。
- 桌面：可用的 Chromium 浏览器，以及 Safari / Firefox 的支持探测与明确降级；不能把 Playwright WebKit 等同于真实 iPhone Safari。
- 网络：LAN、系统 Tailscale、混合与双内嵌；有条件时覆盖不同网络的远程连接与中继。
- 状态：前台、后台标签页、App 后台、锁屏、恢复、网络切换、服务端重启、客户端重启。
- 输入：键鼠、触控、GUI 点击、留黑 / 缩放、失焦释放按键。
- 通知：允许 / 拒绝权限、`sound=false`、重复消息、倒计时更新 / 取消 / 到点、断线与恢复。
- 音频：OpenAudioMc / MCParks 启动、切换、后台与恢复。
- 持续运行至少完成现有计划中的 10 分钟检查；如发现资源增长、掉帧或不稳定，再延长并定位原因。
