## 每个旧版本的测试步骤

建议一次测试一个游戏实例，减少端口和地址混淆。

1. 启动对应 Prism 实例并进入世界。设置中的内置 Tailscale 选项应标明 `Java (test)`。
2. 执行 `/monkey tailscale login`，按浏览器提示完成登录；首次会创建该实例自己的 Java 设备。
3. 执行 `/monkey tailscale status`，使用它显示的地址和实际端口连接。不要复制 26.2 的地址。
4. 手机先通过蜂窝网络连接，确认画面、移动、转向、点击和聊天；执行几个平时常用的操作。
5. 切换 Wi-Fi / 蜂窝网络，确认恢复连接。手机自动重试耗尽时，手动重连一次。
6. 正常退出游戏后再启动，确认无需重新登录，仍能连接。

旧版本沿用原来的 Cloth Config 设置界面和命令，没有移植 26.2 的新面板。
更完整的停止、注销、网页、端口变化及休眠测试见 [26.2 测试清单](TAILSCALE_JAVA_26_2_TEST.md)。
不必为了逐项打勾而重复已经明确通过的相同操作；出现异常时记录版本、步骤和错误文字即可。

## 已完成的自动验证

- 四版本构建通过，26.2 为 73 项 JUnit，其他各为 68 项，均无失败。
- 三个旧版本各自使用 Java 25 / 21 / 17 通过协议及依赖检查。
- 三个最终 Mod JAR 分别通过隔离控制面、WireGuard、官方客户端直连 / DERP、IPv6、
  UDP 中断与恢复、并发长连接、慢读取、半关闭和身份生命周期测试。
- 检查最终包：没有额外混入宿主命名空间的 Gson、Netty 或 BC 类，隔离后的依赖齐全。
- 本次测试带上了真实控制面省略 peer `MachineAuthorized` 字段的回归用例，防止此前超时问题重现。

协议源码共用 `native/tailscale-java/`；三个旧版本的依赖单独重定位，26.2 保留原已验证的依赖方案。
详细打包记录见 [接入记录](../native/tailscale-java/MONKEYCRAFT_INTEGRATION.md)。

## 包、证据和回退

项目内 `outputs/java-tailscale-propagation-2026-10-04/` 包含：

- `packages/`：三个测试 JAR 的副本。
- `deployment.json`：准确安装路径、SHA-256、原包备份位置及验证结果。
- `backup/<mc>/`：各实例原有的 1.4.2 Mod。
- `<mc>/`：构建和互通测试日志。

临时切回原生后端：在对应 Prism 实例的 Java 参数中加入
`-Dmonkeycraft.tailscale.backend=helper`，然后重启游戏。原生登录身份没有迁移或覆盖。
恢复完整原版本：退出对应游戏，移走该实例的测试 JAR，将备份中的原 JAR 放回，保持只有一个 MonkeyCraft JAR。

正式发布待实机测试后再决定。当前包仍是测试版本；长时间运行、注销重登和 Windows 验证不能因构建通过而视为已完成。
